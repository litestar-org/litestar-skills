# litestar-vite — Stream Helpers Reference

Browser helpers for JSON event streams over WebSocket and SSE, added in
`0.28.0`. They own connection lifecycle, reconnect backoff, heartbeat
filtering, duplicate suppression, and sequence-gap warnings. The application
still owns authorization and rendering.

Ship from `litestar-vite-plugin`; no additional runtime dependency.

## Choosing a Helper

Pick the narrowest helper that matches the server route.

| Helper | Use for | Knows queue envelope |
| --- | --- | --- |
| `createEventStream()` | An application-defined WebSocket or SSE route | No |
| `createChannelsStream()` | WebSocket routes generated by Litestar's `ChannelsPlugin` | No |
| `createTypedChannels()` | Typed factory bound to a generated `ChannelMap` (`channels.ts`, `0.32.0+`) | No |
| `createQueueEventStream()` | Routes generated by Litestar Queues, or a custom route deliberately using the same envelope | Yes |

`createEventStream()` is neutral: it parses JSON when possible but assumes no
event names, heartbeat shapes, identifiers, or sequence fields.

## Generic Streams

```typescript
import { createEventStream } from "litestar-vite-plugin/helpers"

const stream = createEventStream({
  url: "/events",
  onEvent: (event) => console.log(event),
  onGap: (gap) => console.warn("Missing events", gap),
})

stream.connect()
// Later:
stream.dispose()
```

Use `buildUrl` instead of `url` when a signed endpoint or token can change. It
runs immediately before every connection attempt, including reconnects:

```typescript
const stream = createEventStream({
  buildUrl: () => `/events?ticket=${encodeURIComponent(currentTicket)}`,
  onEvent: handleEvent,
})
```

## Channels Streams & Typed Channels (`0.32.0+`)

When `ChannelsPlugin` generates `/<channel>` WebSocket routes, let the helper
encode the channel (including `{param}` placeholders via `params`) and build the route:

```typescript
import { createChannelsStream } from "litestar-vite-plugin/helpers"

const stream = createChannelsStream({
  basePath: "/channels",
  channel: "users/{id}/notifications",
  params: { id: 42 },
  onEvent: showNotification,
})
stream.connect()
```

`channel` may be a function. `transformUrl` can attach a current signed token
before each reconnect.

When `TypeGenConfig(generate_channels=True)` (`0.32.0+`) emits `channels.ts` from AsyncAPI 3.0 metadata, bind `createTypedChannels<ChannelMap>()` for compile-time checked channel names, path `params`, and event payloads:

```typescript
import { createTypedChannels } from "litestar-vite-plugin/helpers"
import type { ChannelMap } from "@/generated/channels"

const channels = createTypedChannels<ChannelMap>({ basePath: "/channels" })
const stream = channels.stream("notifications", {
  onEvent: (event) => showNotification(event),
})
stream.connect()
```

## Queue Event Streams

`createQueueEventStream()` understands `QueuePlugin`'s generated task, queue,
worker, global, and custom routes, and owns the queue event names plus the
standard heartbeat, deduplication, and sequence selectors:

```typescript
import { createQueueEventStream } from "litestar-vite-plugin/helpers"

const stream = createQueueEventStream({
  scope: "task",
  taskId: () => selectedTaskId,
  transport: "sse",
  onEvent: updateTask,
  onGap: warnAboutMissingEvents,
})
stream.connect()
```

A custom endpoint opts into the same envelope by supplying `url` or `buildUrl`
instead of a generated-route target.

## Declarative Stream Element

Call `defineStreamElement()` once, then bind connections to ordinary DOM
lifecycle:

```typescript
import { defineStreamElement } from "litestar-vite-plugin/helpers"

defineStreamElement()
```

```html
<litestar-stream url="/events" transport="sse" swap="json">
  <template ls-for="item in $data.items">
    <p>${item}</p>
  </template>
</litestar-stream>
```

The element uses light DOM and dispatches bubbling `litestar:stream-event`,
`litestar:stream-health`, `litestar:stream-gap`, `litestar:stream-open`, and
`litestar:stream-close` events. `preset="queues"` delegates to
`createQueueEventStream()`; generic behavior is the default.

For JSON streams the element replaces `htmx-ext-ws` and `htmx-ext-sse`. Do not
layer both on the same endpoint — two reconnect policies would compete for one
connection.

## Framework Adapters

Optional subpaths. All return the same state fields: `healthy`, `lastEvent`,
`lastGap`, and a bounded `events` buffer.

```typescript
// React
import { useQueueEventStream } from "litestar-vite-plugin/react"

const stream = useQueueEventStream({
  key: taskId,
  scope: "task",
  taskId,
  onEvent: handleTaskEvent,
})
```

```typescript
// Vue
import { useEventStream } from "litestar-vite-plugin/vue"

const stream = useEventStream({
  key: () => projectId.value,
  url: "/events",
  onEvent: handleEvent,
})
```

```typescript
// Svelte
import { createEventStreamStore } from "litestar-vite-plugin/svelte"

const stream = createEventStreamStore({
  url: "/events",
  onEvent: handleEvent,
})
```

React and Vue reconnect only when their explicit `key` or transport changes,
never when an inline callback gets a new identity — so an inline arrow in
`onEvent` does not thrash the connection. A Svelte store connects for its first
subscriber and disposes after its last subscriber leaves.

## Authentication

Authentication stays on the Litestar route.

- Same-origin session and JWT cookies are sent automatically by native
  `WebSocket` and `EventSource` clients. Validate them with Litestar auth
  middleware and guards.
- For a rotating signed URL, use `buildUrl` or `transformUrl`. Keep the
  credential in a property or closure instead of serializing it into markup.
- Native browser WebSocket and EventSource APIs cannot attach an arbitrary
  `Authorization` header. Prefer an HttpOnly cookie. When bearer auth must
  remain, exchange it over authenticated HTTP for a short-lived,
  audience-restricted stream ticket rather than putting a general access token
  in the query string.
- Cross-origin SSE credentials need a credentialed `EventSource` plus matching
  CORS policy. The default design keeps streams same-origin through the
  Litestar port.

For WebSockets, reserve one close code for expired authentication (for example
`4001`) and a different one for a real authorization denial (for example
`4003`). `shouldReconnect(code)` can then trigger application-owned refresh
logic and suppress retries for terminal denials.

## Transport Choice

| | SSE | WebSocket |
| --- | --- | --- |
| Direction | Unidirectional | Bidirectional |
| Reconnect | Native browser behavior | Helper-owned |
| Named server events | Must be enumerated — `EventSource.onmessage` receives only unnamed events | No event-name list needed |
| Auth headers | Not addable during handshake | Not addable during handshake |

## Replay and Gaps

The helper warns about a sequence gap. It never guesses at missing data and
never silently refetches it.

Silent recovery across reconnects requires storage on both sides of a
`QueuePlugin` stream:

- configure Litestar Queues with `replay_limit > 0` (the default is `0`);
- configure the Channels backend with `history=`, for example
  `MemoryChannelsBackend(history=200)`.

Without both, an outage can produce a gap the browser correctly reports but
cannot recover.
